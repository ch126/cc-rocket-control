# CC Rocket Control

用于 CC: Tweaked 与 Create Propulsion 的五引擎同步控制器。
`engine.lua` 是红石手动版；`stabilize.lua` 是红石扶正版；`flight.lua` 是红石扶正＋定高／缓降版；新增 `wired.lua` 是创造矢量引擎有线外设版。
新增实验版 `home.lua` 提供更缓和的扶正、定点悬停和返回发射台上方；**没有自动着陆或塔架联动**。旧版文件保留，便于回退。

## 九引擎回收开发预览（尚不可实飞）

### 统一操作入口（实验版）

单文件打包版 `rocket_bundle.lua` 内置依赖，不会加载 CC 电脑上的旧模块。
先落稳并退出旧控制器，再下载到**新的文件名**（已有同名文件时换名，不删除旧版）：

```text
wget https://raw.githubusercontent.com/ch126/cc-rocket-control/main/rocket_bundle.lua rocket-preview.lua
rocket-preview
```

以上启动默认只读，约 70 KB；磁盘需保留余量，不自动清理日志或校准。
可点击按钮或使用原按键，至少需要 30×16 终端；小屏幕只显示提示，空格/Q 仍有效。
不创建 startup，不在下载后自动运行，不附带伪造的实测配置。
`python build_bundle.py` 重新构建，`python build_bundle.py --check` 检查与源码一致。
`test_rocket_app.py` 直接运行打包产物，避免只测试源码而漏测安装版本。

`rocket_app.lua` 默认只读：显示遥测、阶段、基地状态，任何控制键都不写引擎。
源码入口需要同目录的回收模块及 `home.lua`（仅加载其数学函数）；
普通安装使用上面的单文件打包版，不要仅下载源码入口。

开发接口 `rocket_app --live verified-config.json` 会先验证配置，再**清零九台引擎及六面红石**，
因此不得在空中或旧控制器运行期间启动。进入后仍需 J 记录受支撑的基地参考，E 零油门解锁，
R/F 调节手动油门（带扶正）；V 悬停当前位置，D 下降返航，B 返回点火后返航。
J 仅检查静止/竖直，没有触地传感器，必须由操作者确认落稳。基地目前只保存在本次会话。
零油门手动模式九台均为零，不悄悄启用侧推。空格、Q、Ctrl+T 或遥测故障会请求全部关机；
**空中关机会坠落，不是安全着陆或自动救援**。此入口仍未在用户世界实飞，请勿自行编造配置试飞。

配置必须包含 `profile`（回收实测字段）、`craft`（id、profile 几何质量/惯量、main/top 布局、basis）、
`limits`（主/侧推已验证上限及偏转步进）和 `caps`（九个显式输出上限）。
不提供自动把理论参数标为实测的功能；尚缺现场校准验收工具。
`flight_session.lua` 管理操作状态和模块调用。`test_rocket_app.py` 在异步 CC 模拟器中运行
真实入口、遥测、控制分配及输出后端，验证只读无写入、无效配置无写入、显式 J/E/R 输出、
Q/Ctrl+T 排队写入排空后清零；使用合成配置，不是本舰实飞或全阶段闭环验证。

### 当前舰体：单级下降返航，不接塔架

新增 `telemetry.lua`：并行读取 CC:Sable 的身份、质量、姿态、速度及组装状态，
每项保留读取起止时间；整帧使用最早开始时间，避免旧数据被最后的姿态读取“刷新”。
角速度由连续姿态计算，首次或错误后需要重新积累两帧；间隔/总读取超过 0.25 秒拒绝。
九路就绪还要求输出后端的逐引擎确认未超过 0.6 秒，单纯发现外设不等于输出可用。
仍需实测服务器调度延迟，不宣称同时读取是原子快照。

`telemetry_probe.lua` 是可运行的只读诊断入口，需要同目录的 `telemetry.lua` 和 `home.lua`。
在落稳、退出控制器后运行 `telemetry_probe`，显示 30 次采样的耗时/失败原因。
不保存文件、不控制引擎、不检查输出确认、不产生实飞许可。显示的 Y 是逻辑姿态位置，
不是电脑方块或喷口离地高度。`test_telemetry.py` 使用合成 API 验证读取失败和新鲜度规则。

用户确认尚未搭建可分离上面级及回收塔，因此当前运行路径不执行热分离、机械臂接近或捕获关机。
`mission_runtime.start(..., mode, "descent")` 新增单级下降入口：从经过检查的稳定悬停状态进入
下降时纠偏、必要时提前点火，再持续保持发射参考位置上方 20 格；不要求 `boostbackVerified`，
但仍要求真实有效的竖直制动、顶部侧推及耦合控制校准。省略 entry 保留原 boostback 路径。
这不是地面起飞入口，也不允许拿它接管已经失控的坠落。
不要把这个模块作为 CC 命令运行，或把模拟参数写成实测校准。

新增下降路径的 shadow/模拟驱动提交测试，覆盖连续九路指令、悬停 35 秒、外部扰动恢复，
以及地面启动、快速下坠、超角度、未知阶段拒绝。当前测试仍是合成平面模型，不是本舰实飞。

### 分阶段目标与当前进度

最终目标仍是分阶段 SpaceX 风格回收，不以“计算模块通过测试”代替完成：

| 阶段 | 当前证据与缺项 |
| --- | --- |
| 热分离 | 尚无上面级点火/分离执行接口和联锁测试 |
| 返回点火 | TURN/BOOSTBACK/LEVEL 已接入影子任务调度器；完整耦合平面模拟通过，尚未实飞 |
| 滑行下降并修正落点 | 规划器已连接九输出分配器，纯计算，不控制实际外设 |
| 提前点火、减速对准 | 高度/时间/姿态/控制能力触发，耦合平面模拟通过；尚未实飞 |
| 发射台上方 20 格悬停 | 新运行层已接持续悬停，模拟 35 秒及扰动恢复通过；尚未游戏内验证 |
| 机械臂接近、捕获、承重后关机 | 塔架通信、捕获确认及执行接口尚未实现 |

`engine_io.lua` 是显式调用的九路输出后端，不是可直接运行的飞控入口。模块加载无写操作，
但 `initialize()` 会清零全部引擎/六面红石。它要求九台上限由调用者明确提供，不自行采用
顶部 733 kN；`arm()` 需要新鲜零输出确认，`submit()` 检查编号顺序、每台上限和实际偏转档位。
每台独立写入；停止和零推力切换作废旧的启用命令。`run()` 在退出时等待所有已排队调用
结束，再做最终清零，避免晚到正推力写入覆盖最终清零。持久化零 base override，不恢复旧红石。
输出超时/指令流超过 0.35 秒不更新会锁定故障并请求清零。**这是紧急关机，不是安全着陆保证**；
服务器已排队调用无法撤销，也不能保证失联引擎实际收到清零。每次清理会返回未成功的操作。

`mission_runtime.lua` 默认 shadow，仅显式 live 模式才向已初始化、已解锁的后端提交指令。
不会自行初始化/解锁，也不会生成或伪造实测 profile。返回点火至回收阶段、悬停交接保持完整
九指令帧；`hover_control.lua` 持续反馈控制基站上方 20 格，而不是交接后停止发指令。
输入失效停止生成新指令并报告接管，输出后端仍执行它明确规定的超时关机策略。
统一入口见上文；仍缺初始起飞/标定验收、热分离和塔架捕获的实装验证。

`test_engine_io.py` 在异步 CC 模拟器中验证实际 Lua 后端的启动清零、九路独立推力、
排队期间停止/退出、滑行、所有编号缺失、写入故障和输出阻塞。
`test_runtime.py` 的 live 用的是**记录调用的模拟驱动**，并非真实游戏输出；它验证运行层
向驱动提交的契约。独立平面刚体仿真继续悬停 35 秒并加入位置/速度扰动。
这些分层测试尚不等于真实模组、实时遥测、完整后端和用户舰体的一体实飞测试。

`boostback_plan.lua` 实现小型舰体、64 格水平范围内的转向—返回点火—回正；
要求额外 `boostbackVerified` 和经验证的横向能力，不接受把理论模型标为已实测。
它保持本阶段高度，通过预计弹道交点调整返航速度，然后在回正后交给下降规划器。
不是全尺寸火箭的 180 度翻转，也不包含热分离。高度余量不足时请求应急回正/最大制动，
或在已回正时立即交接减速，不因阶段切换产生无检查的关机。
`mission_control.lua` 连接返回点火与下降/悬停交接，仍然只返回影子指令。
`test_mission.py` 以独立平面刚体方程从距离基地 20 格、向外 1 格/秒的状态运行，
经过 TURN/BOOSTBACK/LEVEL/COAST/BRAKE/HOVER，覆盖喷口渐变与 0/0.2/0.4 秒输出延迟。
这些合成测试不代表当前用户舰体已完成实飞验证。

分配器现在累积有界的“加速度×时间”余量，使低于一档的需求通过间歇真实档位实现，
避免微小纠偏一直被取整为零。转阶段清除旧点火阶段的余量；滑行明确锁住主推力为零，
不会因把水平世界指令旋转到船体坐标而产生微小主推力。滑行角速度超过提前阈值也会
请求点火，不等倾角越界后才反应。

`control_allocator.lua` 同时拟合期望平移和转动响应，枚举真实 1/15 喷口档位，
限幅顶部四台单向推力并约束偏转步进。姿态误差高权重但不是严格零误差保证；
残差明确返回。关主推时无法同时实现侧向加速与零旋转会报告需要有动力支撑。
`recovery_control.lua` 连接几何模型、规划器和分配器，返回九台**建议指令**，
保持 shadowOnly，不调用任何引擎。它核对舰体身份/模型质量，由姿态计算倾角，
输入失效时返回无指令并请求接管，而不是把空指令解释为空中关机。

新增 `CONTROL_AUTHORITY` 提前点火原因。点火后的对准使用位置/速度反馈，不再
沿用自由落体时间预测作为有动力纠偏时域；对准期间闭环保持点火高度，对准后下降。
固定悬停推力下限仅覆盖短暂点火余量，避免模型偏差造成持续爬升。
`test_recovery_control.py` 用独立耦合平面刚体方程测试主喷口+顶部侧推、0/0.2/0.4 秒
输出延迟以及 20%/50ms 喷口渐变，到达 20 格悬停交接条件。模拟采用合成布局、
惯量和顶部 100 kN 上限，**不是用户实测参数，也未验证三维滚转/气动/碰撞或真实 CC 调度**。

新增 `geometry_model.lua`：无外设/文件副作用的稳态几何模型，输入同一船体坐标系中的
质量、重心、逆惯量、引擎中心和方块 facing，输出力、力矩、零角速度下的线/角加速度，
以及底部引擎稳定偏转一档相对中立的响应差。`test_geometry_model.py` 验证六向、
两偏转轴符号、单位、平移不变性和错误惯量拒绝。它**不是校准文件、不接管引擎、不允许起飞**。

模型依据本地安装的 Create Propulsion 1.1.5 字节码：
`VectorThrusterBlockEntity.computeRight/computeExhaustDirectionLocal/getThrustDirectionLocal`，
`ThrusterForceProvider.createSample`，`AbstractThrusterBlockEntity.sable$physicsTick`，
`SimulatedThrustAdapter.applyImpulseAtPoint`。零偏转的推力沿 blockstate facing；底部 up
引擎的正 VectorX/VectorY 分别偏向船体 +X/+Z，斜率为设定值乘 tan(30°)。
内部推力数值在进入 Sable 队列前除以单位倍率（本安装为 1000），不可再次乘 1000。
喷口施力点沿推力轴的额外偏移不改变关于重心的力矩，因为这一项的叉积为零。
CC:Sable 1.3.4 的惯量接口直接读取 MassData，模型不把船体矩阵当成世界矩阵。

限制：输出是无碰撞、稳态推力、零角速度的分析预测，不含喷口渐变、启动延迟、阻挡损失、
气动阻力、地面接触和非零角速度的陀螺项。不会假定真实重力，不从质量单独猜测悬停油门。
用户存档坐标、UUID、检查报告只保留在本地工作区，没有放进公共仓库。

**v0.6.3 修正测试顺序：没有有效校准时，正常启动拒绝 E 解锁；U 只记录参考，不能代替校准。**
撤回“先手动升空再 K”的建议。正常模式禁用 K；旧试喷流程只保留在显式开发测试模式，
不是用户舰体的校准解决方案。新增 `inspect.lua`，落稳且退出飞控后采集质量、重心、惯量和
九台引擎状态，保存独立报告，不点火、不修改引擎、不删除旧日志，也不生成校准。

新增 `nine.lua` **九输出实验控制器**：底部五台仍同步控制，顶部四台默认关闭；
提供单台 1 kN 短脉冲采样、九台统一急停、双调制解调器断线处理和独立主引擎校准文件。
它不是自由落体返航成品，不能自动执行上述回收流程。
启动会尝试清零全部九台，必须落稳、退出旧程序后再运行。
顶部测试需要有效主引擎校准、稳定 V 悬停、基站参考高度上方至少 20 格和可用日志。
测试时暂时取消定高，结束后只恢复扶正，需确认稳定再手动 V。
左右箭头选顶部引擎，O 开始测试；默认仅 1 kN，不能按 733 kN 试喷。
详细接线、限制和安装说明见 [NINE-TESTING.md](NINE-TESTING.md)。
现有 `home.lua` 保持不变。异步模拟测试只验证控制程序，不代表真实游戏试飞通过。

用户确认的新布局：底部 `creative_vector_thruster_0`～`_4` 为主推力；顶部 7 在电脑前侧、6 左侧、8 右侧、5 后侧，喷口都朝外。九台基础推力设置均为 733 kN。顶部四台必须独立控制，**733 kN 是用户设置值，不是建议的姿态控制输出**。该位置映射也不能直接当作 Sable 舰体坐标轴；还需实测姿态响应。

目标高度已定为 **记录的发射参考点 Y +20 格**，不是电脑/喷口的绝对离地高度。按用户最新要求，v0.6.1-preview 改为“主引擎关闭下降、同时侧推修正预计落点 → 余量不足提前点火 → 悬停等待人工回收”，取消单独的 ALIGN 阶段。这是侧推辅助下降，不是完全无动力自由落体；不触地、不夹持、不避障。

计算模块的新规则：

- 从稳定的高空有动力悬停状态请求进入 COAST，不要求水平位置已经对准。每次计算都输出水平加速度建议，利用位置误差、水平速度、剩余高度估计目标平面上的交点并纠偏。`predictedX/Z` 是**不继续施加侧推/主推力时**与目标高度平面的预计交点，不是保证的实际着陆位置；不把“箭体竖直”当成“落点正确”。
- 用保守的横向能力估算“等待侧推响应 → 刹住当前横向速度 → 从停下位置加减速到基地”所需时间。纠偏时间加点火余量超过预计下降时间，或竖直制动高度不足、姿态余量不足、滑降超时，就请求提前点火，并输出原因。点火状态锁定，不反复关机滑降。
- 横向原因触发时至少请求有动力支撑，而不是因竖直速度尚小又输出零推力。高空提前点火后的制动阶段时限随剩余高度增加，但最多 300 秒。最终仍需进入已验证的定点定高控制。
- 新增 `version=2` 飞行模型、`coupledRcsVerified`、`lateralAccelMin` 和 `lateralResponseDelay` 前置条件。横向能力必须是在**同时维持姿态**时测出的可用能力，不能把单台引擎的水平推力当成可独立分配的平移能力。未经这些标定，模块拒绝开始；旧版 profile 也被拒绝。模拟里的标记和参数只是测试夹具，不是可用于实飞的配置。

新增文件与实际完成范围：

- `recovery_plan.lua`：无外设/文件/红石副作用的计算模块，包含 COAST/BRAKE/HOVER/FAULT 阶段、随下降速度变化的制动高度、横向时间预算、延迟余量、至少 5 格高度余量、20 格目标、身份/质量/九台连接检查、点火后不重复关机、积分限幅。**只输出建议，不控制引擎，也没有姿态分配器。**故障不输出“零推力”等同安全的错误建议，仍需未来飞控定义并测试接管策略。
- `recovery_check.lua`：可在 CC 运行的**只读**九引擎连接/接口上限检查，不改变任何推力或偏转，不会帮你关掉正在工作的引擎。
- `test_recovery_plan.py`：使用明确的合成物理参数，在三种重力/推力组合及 0.4 秒输出延迟下测试收敛到 20 格上方；新增水平偏移、残余漂移和高空横向时间不足提前点火测试，覆盖前置条件、阶段锁定、数据失效、超时和只读外设检查。横向测试使用独立的理想水平执行器和 0.2 秒延迟，**没有验证真实侧喷口的旋转/平移耦合**，合成参数不可作为用户舰体的实测配置。

### 自动悬停与自动点火的边界

- R/F/T/G 接管推力并关闭定点／定高／返航，保留可用的扶正；C 退出全部自动控制、回中但保留推力；H 关闭扶正时也退出定点／定高；V 再按一次退出定点／定高但保留扶正和当前推力。空格停推，Q 退出清零；**空中停推会下坠，不是安全降落**。
- 返航未完成超过180秒、返航中降到发射台参考高度＋8格以下，或水平速度超过3格/秒，会取消导航、回到竖直定高。此时不会继续刹住水平漂移，必须手动判断。姿态恢复优先级更高，按上文处理；定高期间的竖直速度和原有传感器／外设故障保护保留。
- 发射台只记录本次运行，不随校准存档保存；重新加载校准也清除发射台记录，防止沿用旧坐标。XYZ 是模组逻辑姿态参考点，**不是喷口／箭体底端位置**，高度差不等于离地净空。返航路径必须由玩家确认没有障碍物，留足箭体和塔架间距。
- 1.1.5 的偏转仍按1/15档取整，存在残余摆动，不能承诺厘米级定点。此次减慢接近速度来留出制动时间；服务器延迟、载荷、引擎布置和气动变化仍可能使控制失效。
- 扩展模拟中，横向加速度响应加倍时，虽然能返回附近，但会出现约0.6格/秒的往复移动，未满足持续到达条件。这说明固定参数还不能覆盖所有动力学；如果 V 无法稳定保持位置，先退出定点并反馈现象，不要继续尝试塔架回收。
- 自动化测试运行实际 Lua：包含水平扰动恢复、返回后持续位置／速度边界、手动取消、启动限制、校准存档，以及原有异步按键／外设／急停回归。对比测试包含响应系数±30%、100ms接口延迟和较慢喷口，验证模拟中的偏转切换减少。
- **只是简化动力学模拟通过，不是 Minecraft 实飞验证。** 五台同步推力上限仍是每台733 kN。先在备份世界试 H，再试 V，最后近距离试 B；不要直接在正式塔架上测试回收。

本地测试（Python 需安装 Lupa）：`python test_home.py`、`python test_stability.py`、`python test_wired.py home.lua`。
本机 Windows 的 Lupa/Lua 5.2 长时间异步测试曾出现原生访问冲突；测试调度器保留运行库并停用其 Lua GC 以绕过，游戏中的控制代码没有改动 GC。模拟不能替代 CC 环境实测。

## v0.4.0 有线外设精细推力（wired.lua）

适用于已确认接线的这台电脑：底面有线调制解调器，远程外设 `creative_vector_thruster_0` 到 `_4`，每台基础推力上限 **733 kN**。五台共同百分比调节，不做差动控制。

### 重要：1.1.5 的接口精度与先前说明更正

逐项检查了本地 `createpropulsion-1.1.5.jar` 的实际实现，而不仅是方法的浮点参数：

- `ThrusterComputerHelpers.setThrottleNormalized` 执行 `floor(clamp(value,0,1)*15+1e-6)`，然后调用整数档油门。因此 `setThrustNormalized(0.352)` **并不能**获得真正35.2%的油门。
- `VectorThrusterBlockEntity.setVectorCoordinates` 把两轴的绝对值乘15再四舍五入，因此 `setVector(0.02,-0.01)` 实际会归零，不能当作精细偏转。
- 创造矢量引擎的 `setThrustOutput` 则直接保留浮点基础推力，乘以油门及环境因子。新版用它调整基础推力，整数油门只用0（关）和15（开），绕过油门档位限制。
- 例如1.1%指令为每台 `setThrustOutput(8063)`，配合15档使基础推力为8.063 kN；这是基于本地 `thrustUnitsPerKn=1000` 的换算。界面显示的是**基础推力指令，不是测得的实际推力**。
- 偏转仍是有效的1/15档，最多±3档；没有承诺连续小数偏转。自动高度环使用连续推力计算，不再把结果四舍五入成红石档位。

参考：[项目外设接口说明](https://github.com/Propulsion-Team/create-propulsion-simulated/blob/main/wiki/ComputerCraft-Peripherals.md)。不同构建的实现可能不同，以实际安装的 JAR 为准。

| 按键 | 功能 |
| --- | --- |
| R / F | 同步推力增加／减少1个百分点，每台7.33 kN |
| T / G | 同步推力增加／减少0.1个百分点，每台0.733 kN |
| W / S、D / A | 手动两轴偏转增加／减少1档，限±3档 |

| Q / Ctrl+T | 退出并尝试逐台清零 |
| U / K / H | 新的竖直基准／脉冲校准／自动扶正 |

### 存档与输出可靠性

- 自动保存到 `/rocket-wired-calibration-v2.cfg`，与红石版存档隔离。**第一次迁移必须重新U/K，不能复制旧标定结果。** 成功后重启自动验证并加载，仍为零推力。身份、质量、引擎名称顺序、控制方式、推力上限和换算系数不符会拒绝加载。
- 不沿用上次飞行高度；加载校准后在起飞点按J。改变引擎朝向、重心、结构或参数必须重新校准，即使质量和ID没有变化。
- 733 kN和1000换算系数是本实例的已确认设置，写在程序顶部。换世界或修改模组配置后须重新核对，不能盲用。
- 按键、传感器、五个引擎输出任务分别处理。每台引擎只有一个正常写入任务；不让五台逐个串行等待。它们接收相同目标，但**不保证物理更新完全同时**。
- 急停会使旧指令失效；正在等待的调用返回后立即处理零输出。重新解锁须等五台清零确认，不能因快速按E让旧非零指令再次启用。
- 正常运行时发现断线／写入错误会锁定故障并停止其余输出，需要修复并重启。输出任务超0.6秒无完成确认、已解锁时姿态超0.5秒未更新，也触发停机；原姿态环0.35秒保护仍在。
- 清零会分别尝试油门0、基础推力覆盖0、偏转0；某个调用失败不会跳过其他引擎。看到 `CLEAR FAILED` 表示**未能确认全部清零**。
- 外设断线后无法发送停机命令给那台引擎。世界暂停、服务器卡死、区块卸载、进程强制中断也不受软件保护。五台有推力时发生非同步停机会失衡；请备份世界，不把此程序当作可靠回收系统。
- 退出保留基础推力覆盖为0（写入引擎NBT），不自动调用 `clearThrustOutput()` 恢复滚轮推力。若回退红石版，必须先确保原红石信号为0，再在连接状态下将五台油门清零并调用各自的 `clearThrustOutput()`，最后断开外设接管。只换回旧Lua文件并不足以恢复红石控制。

### 按键响应

按键监听和传感器采样现在运行在独立协程中；传感器等待主线程返回时，不再吞掉按键事件。`R/F/W/S/D/A` 支持长按，每次重复调节至少间隔0.12秒；`E/H/K/V/N` 等切换键仍只处理首次按下。空格急停、Q／Ctrl+T退出可在传感器等待时处理。

实现依据：[CC parallel 的独立事件队列](https://tweaked.cc/module/parallel.html)。

### 校准保存与加载

- `K` 成功后自动保存扶正基准轴、两轴响应矩阵、校准推力、质量、舰体 ID 到 CC 电脑的 `/rocket-calibration-v1.cfg`，不是 Windows 上的文件。
- 重启自动加载，校验格式、有限数值、轴正交性、矩阵有效性、舰体 ID 及质量差不超过5%。损坏或不匹配会拒绝加载。
- 加载不会启用引擎：仍是解除控制、零推力。确认界面出现 `Loaded; verify craft unchanged` 后，才自行 E、调推力、H。
- 解除控制时 `P` 手动保存，`L` 重新加载。正常写入先使用 `.tmp`，再把上一版保留为 `.bak`；主文件缺失时可读取备份，主文件损坏时不会静默回退。保存失败显示 `SAVE FAILED`，当前内存中的有效校准仍可使用。
- 改动接线、引擎朝向／创造推力、重心或结构后必须重新 U／K，即使 ID 和质量没有变化。程序不能识别所有这种变化。只有成功的新校准才替换存档，失败不会把坏结果写进去。
- 旧 `stabilize.lua` 没有存档，升级后首次需要重新校准。

### 定高与有限缓降

1. 第一次按原 U → E → 调油门 → K → H 流程完成扶正。U 必须在实际竖直、静止的起飞位置使用，同时记录本次高度基准。
2. 如果已加载存档，不要为了设高度再次按 U（U 会清除内存里的校准）；在起飞位置解除控制、竖直静止时按 **J** 单独记录本次高度基准。加载时不会恢复上次飞行的高度。
3. 在 H 扶正下，手动调到接近悬停：推力2～13档、升降速度绝对值小于0.4格/秒持续2秒、倾角小于8度、高度至少为本次基准＋2格，再按 **V** 捕获当前高度并启用定高。屏幕显示 `HOLD ALT`。
4. **N** 将目标高度以0.3格/秒下移，最多3格，且不低于本次基准＋2格；到目标后重新定高。再次 N 暂停缓降并锁定当前高度。这是目标变化速度，不保证实际降速严格等于0.3。
5. **V** 退出高度控制；**R/F** 退出高度控制并手调油门；**H/C** 回手动。上述操作保留当前油门（R/F另加减1档）。空格、E解除控制、Q退出会清零。

高度取自姿态参考点的世界 Y，不是箭底到地面的距离，**没有地面探测，不是自动着陆**。倾斜会影响参考点高度；16级红石、引擎响应和世界物理可能造成上下振荡。
定高推力限定在捕获值±3档且处于原校准的0.5～2倍范围内；超过边界显示 `THRUST LIMIT`，不代表仍能保持高度。
定高时倾角超过15度、测得升降速度超过4格/秒，以及原有传感器／采样异常保护，均会清零停机。空中停机会坠落；请备份世界并先做低空测试。

通过 Lua 5.2 仿真：延迟接口、真正挂起接口期间的按键、长按限速、急停、跨重启存档、损坏／不匹配拒绝、磁盘写入失败、定高／缓降及手动接管。尚未在 Minecraft 中实飞验证。

### 首次运行顺序

1. 让箭体实际竖直、静止，等待界面出现质量和速度。按 `U` 记录此时箭体朝上的轴。
   程序不知道你的箭头在哪，不能把倾斜的箭体当作竖直标定。
2. 按 `E` 启用，再用 `R/F` 手动调整推力。先完成低推力、低高度试验，不直接在高空运行。
3. 在箭体接近竖直、几乎没有转动、能自由发生小幅转动时按 `K`。
   程序保持当前油门，依次对 front/back、right/left 发出正反2档偏转，约3.6秒（低TPS会延长）。
   **该步骤会实际改变喷口、使箭体转动**，不是只读检测。夹臂或地面硬锁住箭体会导致标定失败；应使用允许两轴转动的试验架，或可控的低空试验条件。
4. 看到 `calibration OK` 后，按 `H` 开启 `HOLD`。它只尝试扶正，仍要用 `R/F` 控制升降。
5. `H` 再次按下退出扶正；`C` 取消标定/扶正并回中，均保持油门。`空格` 停机解除控制；`Q` 或 Ctrl+T 清零退出。

标定时若倾斜超过12度或转动过快，会停止全部输出；降低创造引擎基础推力/油门后重新竖直标定。
若提示无有效响应，检查接收频率、推力、箭体是否被固定。不要通过取消保护来跳过标定。
若标定结果过期（更换引擎推力设置、接线、重心或结构），重新运行 `K`；标定不跨程序重启保存。

### 控制范围与限制

- 从连续两次姿态计算本体坐标角速度，兼容 CC: Sable 的 `{v, a}` 四元数与原始 `{x,y,z,w}` 格式，不依赖后端角速度的坐标约定。
- 每次采样后等待0.1秒，实际频率受接口调度影响，以 `Sample dt` 为准；两轴PD控制，输出限制为每个方向最多3档，无积分累积。
- 标定测得两路信号对两轴角加速度的响应矩阵，可识别交换轴和反接；弱响应、重叠轴、正反不一致会拒绝启用。
- 油门在标定值的0.5～2倍内做近似比例补偿；离开该范围会退出扶正、喷口回中，但保留你设定的手动油门。零油门不能扶正。
- 标定不是精确系统辨识：气动、喷口延迟、红石延迟和引擎非线性会影响结果。强响应、严重摆动时停止试验并调整推力配置。
- 3档限幅、16级红石精度可能产生小角度残差；不保证悬停或精准对接。
- 检测到传感器错误、结构变化、质量变化超过5%、扶正时采样间隔超过0.35秒、倾角超过25度或角速度超过1.5rad/s，会解除控制并清零。**这是试验停机策略，空中触发会下坠，不是自动救援。**
- 顶面不使用；五台引擎仍然同步，无法独立控制绕箭体长轴的自转，无法主动保持位置。
- 关闭电脑界面不会停机；区块卸载或强制中断不能由软件保证无线接收端清零。

已进行 Lua 5.2 数学、状态机、异常清零及简化自由刚体闭环测试；尚未在你的 Minecraft 世界实飞验证。

## 接线

方位均为 CC 电脑自身的相对面；front 是屏幕面，不是世界北方。

| CC 输出面 | 无线频率 | 接收端 |
| --- | --- | --- |
| front | 独立频率 F | 5台引擎同一偏转方向 |
| back | 独立频率 B | 5台引擎与 F 相反的偏转方向 |
| left | 独立频率 L | 5台引擎另一轴的一个方向 |
| right | 独立频率 R | 5台引擎与 L 相反的方向 |
| bottom | 独立频率 T | 5台引擎的推力红石输入 |

电脑旁的无线红石链路设为发送端。F/B/L/R 对应推进器自带的方向无线接收频率；T 的接收链路输出红石到每台推进器。
五种频率必须互不相同，且不能与其他机器串频。所有引擎安装朝向应一致；否则要调整各引擎接收频率，使其实际偏转同步。
保持信号路径独立，不要用会把强度放大为15的中继器；先确认接收端可分别收到1、2等模拟信号。
本程序不连接推进器外设，不要同时让另一台电脑通过外设接管这些推进器。
top 面不使用，也不会被程序改写。

## 使用

将单文件 engine.lua 放入 CC 文件系统，运行 `engine`。仓库发布后，在 CC 命令行逐行输入：

```text
wget https://raw.githubusercontent.com/ch126/cc-rocket-control/main/engine.lua engine.lua
engine
```

更新时先退出控制程序，再下载为 `engine-new.lua`，确认下载成功后备份旧文件并更名。
无需安装到 startup.lua，避免开机自动进入控制界面。CC 的 HTTP 下载功能需要开启。

| 按键 | 功能 |
| --- | --- |
| E | 启用控制／解除控制，切换时油门和方向清零 |
| R / F | 油门增加／减少1档，范围0～15 |
| W / S | front/back 轴偏转增加／减少1档 |
| D / A | right/left 轴偏转增加／减少1档 |
| C | 喷口回中，保持当前油门 |
| 空格 | 立即清零输出并解除控制 |
| Q 或 Ctrl+T | 清零输出并退出 |

按键为逐次点击调节，忽略键盘长按重复；松开键后设定保持。方向值范围为-15～15，是信号档位，不是角度。
正负值对应电脑输出面，不保证对应箭体运动方向。先固定箭体、零推力检查喷口朝向，再从1档油门测试。
五台引擎各自的创造推力设置仍需在游戏内配置；15档代表请求各自的满档输出，不是固定牛顿数。

## 限制

- 五引擎共用控制，无独立差动推力，也无独立滚转控制。
- 无姿态反馈、定高、自动着陆和塔架控制；关闭电脑界面不会停止程序或油门。
- 程序正常退出、Ctrl+T或可捕获错误时会尝试清零五个输出；进程强制中断、区块卸载、无线信号丢失等情况不能由 Lua 保证接收端归零。
- 清零指电脑输出，真实推进器和无线传输可能存在响应延迟。
- 无需额外安装模组；当前目标环境 CC: Tweaked 1.120.2、Create Propulsion 1.1.5。

接口依据：https://tweaked.cc/module/redstone.html
